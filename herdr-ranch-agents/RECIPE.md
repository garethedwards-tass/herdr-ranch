# Agents

Herdr's agents list with what Claude Code knows about each of its sessions, in the sidebar of the mod-buttons layout (its `agents` block), in place of Herdr's own `agents` mod. `main.js` is a copy of that mod (Herdr 0.1.15) with a few marked changes, so everything it does stays: priority and grouped sorting, pins, time since the last change, Herdr's sub-agent trees and folding, the narrow rail.

## What you see

- **Fold:** a chevron before "Agents" in the header; a click folds the panel to its 42px header (with the number of agents after the name), so Spaces takes the room, and again gives back the height it had (`layout.resize` on the `agents` block to `px` 42, then back to the weight kept in shared `sidebar.fold.agents`; folded = the block has a px size; the layout's `min` for the block is 42).
- **Account filter:** once Spaces has an account, a row of chips under the header: All, each account, then the default account (Default, or the name it was given). A chip shows only the agents on that account: an agent's space's own account, else the account of the repository it works in on its machine (`agentAccount`, the same `accountOf` as Spaces). The choice is kept in the panel's `localStorage` (`agents.account`), apart from Spaces' own filter; a removed account shows every agent. It hides rows only: Herdr's agent order (`setAgentOrder`, for next and previous agent) keeps every agent. With every agent hidden, the list says "No agents on this account."
- **Agent pill** at the far right of every agent row, in the style of the Spaces git pill (84×20, rounded 4, a `color + "55"` border and `color + "14"` fill, 12px text): the agent's status (Herdr's spinner, ring, dot or `!`, which no longer sits beside it), the model family (`Opus`, cut short) and the context in use (`38%`, semibold). Tinted `ansi2`, `ansi3` from 60% and `ansi1` from 85%, `blocked` when it needs you or Claude Code stopped it (its own `<synthetic>` reply, `isApiErrorMessage`: the pill then reads `limit` for a usage limit, else `error`, and the menu's summary quotes it, e.g. "You've hit your 5-hour limit · resets 3:30pm"; such a reply never changes the model or context, and the next real reply clears it); grey with its program name and `—` for an agent without Claude Code's records (`…` while they're read). No tooltip (the menu has it all). A click on it, or a right-click anywhere on the row, opens the agent's menu.
- **Agent menu** (popup at the pointer, 280 wide, as high as its rows): a summary (title; model and effort; a context bar with `36% · 364k`; tasks done and subagents running), a divider, then one row per action: **Usage details ›** (opens the stats popup), **Go to terminal** (`pane.focus`), **Pin to the top** / **Unpin** (`terminal.pin`; the row's hover pin is gone, so its time always shows), **Copy session ID**. A new action is one entry in `menuItems()`.
- **Stats popup** (Usage details; at the pointer, 320 wide): the session's title; Model (`Opus 5.5 · medium effort`); Mode when not normal; Context (`364k of ~1.0M (36%)`) with a bar; This conversation: Replies, Output tokens, Input (new and from cache), Cost and Lines when Claude Code saved them (`cost-state`), Running for; Tasks (`☑ ◐ ☐`, n/m done); Subagents (`●` running, `✓` done; type and description). A note says where it comes from and that the window size is an estimate. Esc closes.
- **Under the agent's row** (unfolded, not on the rail): its task list as one row (`3/7` and the task in progress, or "All tasks done"; a click unfolds every task with its glyph), then each running subagent (spinner, type, description).

## How it behaves

- **Which session:** every 4 s, for each agent whose `app` is `claude-code` on this computer: Claude Code's live sessions (`sessions/*.json` in `~/.claude` and in every account's Claude Code folder from Spaces' shared `ranch-accounts`, read every 15 s) in the terminal's folder; with several there (a background session can share the folder), the one whose `pid` is the terminal's foreground process (`hc get <terminal> --json`, kept while it still matches), else the one whose title (`ai-title` or `custom-title` in its conversation) or name is the agent's title.
- **First read** of a conversation (`<that session's config folder>/projects/<folder, non-alphanumerics as ->/<session>.jsonl`, often tens of MB): one `sh` call with `grep` for the lines that matter (titles, mode, cost-state, TaskCreate/TaskUpdate/Agent calls and "Task #n created" results), the newest reply from the last 2 MB, and every reply's id and usage (`grep -o`), then the file's size.
- **Where each agent works** (`places.js`): every session record carries its folder, which follows a `cd` or a worktree; the latest main-thread one is `st.cwd`. Every 3 s the list writes `shared("ranch-agent-places")` = `{ <terminal>: { cwd } }` when it changed, for the Spaces list's agent badges. A terminal whose Herdr folder matches no session (its folder moved, or Herdr's is out of date) is matched by its foreground process (`hc get`).
- **Codex agents** (`codex.js`): every 15 s the newest 60 conversation files changed in the last 3 days in `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` (listed by `find`, so no command line holds every file), by the fields `grep -o` picks from their first line wherever they are in it (`id`, `cwd`, `source` "cli" or none; subagents, which have a `parent_thread_id` or a `source` object, are left out). A Codex agent's conversation is the one in its terminal's folder whose name (`~/.codex/session_index.jsonl` `thread_name`) starts its title ("Review code | clif"), else the newest there (then only sure of it when no other Codex terminal shares the folder: Restart is offered only for a conversation it is sure of). One `sh` call reads the whole lines added since last time (`tail -c +offset`, stopping before a line Codex is still writing; `awk` keeps the newest `turn_context`: model, effort, and the newest `token_count` that has usage: `last_token_usage.total_tokens` of `model_context_window`; one with `info` null is a rate-limit update): every tick while it works, every 20 s otherwise. Its pill shows the model's last word ("Sol" for gpt-6.1-sol) and the context in use, coloured like Claude's; its menu: the conversation's name, "GPT-6.1-Sol · medium", the context bar, then Usage details, Go to terminal, Pin, Restart, Copy session ID. Usage details (Codex): model and effort, the context bar, turns (`task_started` records, counted in each read), output (and reasoning) and input (new · from cache) from the newest `total_token_usage`, and how long the program has run (`ps -o etime=`).
- **Restart a Codex agent** (`restartCodex`): only when it isn't working, has a shell behind it, and nothing is typed in its prompt (an x typed shows alone on the `›` line, then is removed). It types `/quit` and Enter (ctrl+c twice if it hasn't quit in 2.5 s), then `sh <app home>/data/herdr-ranch-agents/revive-codex-<terminal>.sh`: `cd <its folder>`, `CODEX_HOME` as the running one had it (else unset), `exec codex resume <its options> <id>`. Its options are kept (an unknown one stops it: restart by hand); a first prompt, `--last`, `--all`, an earlier session and `-C` (the script already goes to that folder) are left out; with `-C`, a relative `--add-dir` or `--image` stops it. When Codex prints `codex resume <id>` as it quits, that id is used. Done once Codex reports its status again.
- **Antigravity agents** (`antigravity.js`, `agy-turn.js` from `shared/`): every 15 s agy's `cache/conversation_metadata.json` (title, steps, folders) and `cache/last_conversations.json` (the newest per folder), read with `cat`. An agy agent's conversation is the one agy names newest in its terminal's folder, else the newest there; with two agy terminals in one folder, the one its process holds open (`brain/<id>` in `lsof`), else not sure (no Restart). Its numbers: the newest `gen_metadata` rows of `conversations/<id>.db` (sqlite, read-only; immutable once agy has closed it), a protobuf without a schema: 1 → 9 → 10 holds the tokens in context (1) and the limit compaction works to (4, 512,000 for Gemini 4); a row of another shape gives nothing. Model and effort from agy's footer line on screen ("auto · Gemini 4 Neon · high · …"). Every tick while it works, every 20 s otherwise. agy sets no terminal title: the row's detail is the conversation's title. Pill: the model's last word ("Neon") and the context; menu like Codex's. Usage details: model calls (turn rows) and output and input (new · from cache) added up from each row's call tokens (1 → 4: 2, 3, 5), only the rows after the last read (`idx >`), and how long the program has run.
- **Restart an Antigravity agent** (`restartAgy`): like Codex's: not working, a shell behind it, nothing typed (agy shows a placeholder in an empty prompt, so an x is typed and must show alone on the `>` line). It presses ctrl+d twice (agy's exit at an empty prompt), then `sh <app home>/data/herdr-ranch-agents/revive-agy-<terminal>.sh`: `cd <its folder>`, `exec agy <its options> --conversation <id>`. A first prompt (`-p`, `-i`), `-c` and an earlier `--conversation` are left out; an unknown option, a subcommand or `--remote-agent` stops it. agy prints `agy --conversation=<id>` as it quits: that id is used.
- **Restart safety (Claude Code):** /exit is used only for a session `claude agents --json` lists as interactive (/exit only detaches a background one); a session it doesn't list or that doesn't offer /stop is left alone. Slash-menu matches stay on one line, so the typed prompt never counts as the menu's entry. The footer's "← n agents" is overridden only by subagent records that are all done and at least as many as n. Every Agents list (one per window) sees a Restart ask in shared `agents.restart`; each writes its id as `claimed`, and after 600 ms only the one whose id is still there acts.
- **Worktree marker** (`worktree.js`): an agent working in a linked git worktree has, after its name, a branch icon and the worktree's folder name (11px `accent`, at most 96 wide, no tooltip). Its menu (a click on the pill, or right-click) says it under the summary: a branch icon and "In a worktree of <repo>" (12px `accent`), then the full path (11.5px `dim`), and is 38 higher. Agents in a main checkout or outside git have none. The folder is where it works now (a Claude Code agent's session `st.cwd`, else the terminal's folder); every 5 s the list asks `git rev-parse --path-format=absolute --show-toplevel --git-common-dir` for folders not read in the last minute: a common dir other than `<top>/.git` is a linked worktree.
- **After that:** only what was added (`tail -c +offset`, whole lines), every tick while the agent works, every 20 s otherwise. Subagents from `<session>/subagents/*.meta.json` (newest 8) and whether their call returned.
- **Counting:** a reply split over several records counts once (by its message id); subagents' own usage isn't included. Context is the newest reply's input, cache reads and cache writes. The window is 1M when the model was asked for with `[1m]` or the context is already past 200k, else 200k (Claude Code doesn't record it).
- **Tasks:** a TaskCreate gets its number from its result; TaskUpdate sets the status (or removes it when deleted).
- **Subagents:** done when `meta.json` says `finished`; without that, a foreground one is done when its call returned, a background one stays running.
- Read only. Nothing leaves the computer; only titles, statuses, task subjects, subagent descriptions and counts are kept.

## Built from

- `mods/herdr-ranch-agents/main.js`: a copy of Herdr's `mods/agents/main.js` (0.1.15). After a Herdr update: copy its `agents/main.js` again and re-apply these.
- `extras.js`: `liveAgents` (agents() plus agents that stopped reporting a status, found by their pane; the list and the watcher both use it), `start` (the watcher), `snapshot`, `statsChip`, `statsMenu` (with `menuItems`, `menuHeight`), `claudeRows`, `statsView`, `modelName`.
- `revive.js`: `bringBack`/`revive` (stop a quiet Claude Code session with `/stop`, quit its session list, then a script typed with `hc keys` goes to the session's folder and starts Claude Code again with the running one's options and `--resume <session id>`; the script is written before any key is typed). Helpers: `keysFor`, `promptText`, `runningAgents`, `busyTitle`, `busyScreen`, `vimInsert`, `envVar`, `scriptFor` (tested in `tests/agents.test.mjs`). `liveAgents` keeps a row being brought back while its pane is a shell; the watcher keeps each session's `configDir` and `cwd`.
- `accounts.js`: a copy of `shared/accounts.js` (`accounts`, `envScript`).
- `claude.js`: `liveSessions`, `configDirs`, `pickSession`, `projectDir`, `firstRead`/`parseFirstRead`, `readSince`, `apply`, `totals`, `windowOf`, `tokens`, `subagents`/`subagentOf`, `taskList` (tested in `tests/agents.test.mjs`).

## Watch out

- Claude Code's files are internals, not an API: a new version can rename a record. Everything reads what fits and leaves the rest out; check the popup after a Claude Code update.
- Only this computer: agents on other machines get no chip.
- Herdr's own `agents` mod writes the same pins and order: show only one of the two.
- Bring back drives Claude Code's screen (its prompt, slash menu, `/stop` and session list): a Claude Code update can change them. Every step reads the screen first and stops at anything unexpected; it refuses while the agent looks busy (title spinner or "esc to interrupt"), has an unsent message, uses vim keys outside insert mode (or its vim setting can't be read), has a background agent running, or is the terminal's own program (no shell behind it); and on options it can't repeat.
- An agent that stopped reporting a status shows (`liveAgents`), but Herdr's next/previous agent keys skip it: `setAgentOrder` ignores terminals Herdr doesn't count as agents.

## Done when

- `herdr-app check mods/herdr-ranch-agents` passes, and the mod-buttons layout's sidebar shows it.
- Each Claude Code agent shows a percentage; its menu names the model and effort, and the numbers grow as it works.
- An agent that makes a task list shows `n/m` under its row, and a running subagent shows with a spinner until it returns.
